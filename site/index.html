Rouster

A routing protocol suite in Rust

Rouster is a routing protocol suite in memory-safe Rust. It fuses BIRD’s and Holo’s core architecture, keeps FRR compatibility strictly at the edge, and adds native source address validation.

Get started Read the white paper

What it is

One daemon family, four load-bearing ideas, all in memory-safe Rust.

  • A typed, multi-table core

    A BIRD-style typed multi-table RIB sitting on a Linux netlink dataplane. Interfaces, addresses, routes and neighbours are mirrored from the kernel; static routes program with ECMP and non-main tables; VRF devices keep their own tables without leaking into main; SIGHUP reloads the config. The whole suite is Rust with zero unsafe in protocol code (three audited kernel helpers excepted), one async binary, multi-core from day one.

  • FRR compatibility, strictly at the edge

    Unmodified FRR staticd, bgpd and ospfd attach to rousterd as their zebra, and their routes reach the kernel through the Rust RIB. The ZAPI wire codec is byte-pinned against a real FRR 10.2.2 binary — captured from live exchanges.

  • Native protocol daemons

    bgpd: RFC 4271 FSM and codec, 4-byte AS, MP-BGP v4/v6, route reflection, route-server mode, graceful restart, RFC 7606 error handling — with RPKI (RTR, ROV, ASPA, RFC 9234 roles) in the decision path from the start. ospfd: the RFC 2328 stack end-to-end, plus OSPFv3 on the same AF-generic codebase. bfdd: RFC 5880–5883. IS-IS joined at HEAD, after the v0.1.0 tag.

  • Source address validation, native

    Unique among general-purpose suites (FRR, BIRD, Holo): a SAV Information Base fed from the RIB and config, the IBA/IBB/PBA/PBB validation-mode rule model, uRPF-family rule generation (RFC 3704/8704), and enforcement through rp_filter or nftables backends. Monitor-only by default — drop mode refuses without an explicit opt-in.

Live FRR interop, per protocol

  • BGP

    Two real FRR 10.2.2 bgpd instances peer iBGP Established through rousterd; BGP-learned prefixes reach the kernel (proto bgp), stable over a 60 s soak with zero reconnects.

  • OSPF / OSPFv3

    Native ospfd vs real FRR ospfd: Full adjacency, each remote loopback installed proto ospf, both directions. OSPFv3 reaches Full adjacency with real FRR ospf6d and exchanges routes both ways.

  • BFD

    RFC 5880–5883 state machine; single-hop TTL-255 enforcement is receive-side and kernel-proven on both address families, feeding bgpd’s fast-down path over ZAPI-BFD.

  • IS-IS at HEAD

    TLV-native link-state IGP (ISO 10589, RFC 1195/5301/5303/5305) with FRR 10.2.2 isisd as the interop oracle — the FRR interop smoke is green, recorded twice.

  • RPKI / RTR

    The RTR client is interop-proven against a real gortr v0.14.7 cache, feeding RFC 6811 ROV and ASPA verification into the BGP decision path.

  • The ZAPI wire itself

    Every wire format is empirically pinned against the real FRR 10.2.2 binary, captured from live exchanges.

Status & quickstart

v0.1.0, tagged 2026-10-14

“The first tagged release: the ZAPI-interop core, all four SAVNET slices, three native protocol daemons with live FRR-interop proof on every wire, and the management plane’s foundation — gated at 1468 tests, a 34-script container smoke suite, and Linux CI.”

The three daemons are bgpd, ospfd and bfdd; IS-IS followed at HEAD. The management plane’s foundation is vtyd (a vtysh-compatible VTY server with Cisco-style grammar), configd (transactional config with atomic staged apply and automatic rollback) and rousterctl (a read-only operator CLI).

Release notes for v0.1.0. Since the tag, HEAD has advanced 36 commits; the current gate stands at 1622 tests and 37 smoke scripts (2026-10-15).

Quickstart

Needs Linux (netlink); the smokes additionally need Docker and a locally cached FRR 10.2.2 test image.

cargo build --release
./target/release/rousterd --config rouster.conf
./scripts/run-smokes.sh

Full instructions, including the rouster.conf examples, in the repository’s README.

Where it stands, honestly

  • Not feature-parity with FRR, and that is explicit: the plan positions FRR as spec and oracle, with parity a stated non-goal.
  • YANG northbound / gNMI is not yet present — management today is vtyd + configd + rousterctl.
  • Protocol remainders are deferred and tracked in the repo: IS-IS (LAN circuits/DIS, LSP fragments beyond 0, authentication wiring), OSPF (graceful restart, E-LSAs, AF instances, more), BGP (MRAI queues, runtime policy reload, ROV-informed path selection).
  • The nightly smokes workflow has no green run recorded yet — see the badge note above.
